Kontrol keuangan dan penerimaan
Pembukuan dan laporan
Saldo awal harus seimbang. DP sebelum penyerahan dicatat sebagai uang muka sesuai kebijakan
finance; pelunasan tidak menggandakan pendapatan. Koreksi jurnal menggunakan pembalikan. Laba
rugi, neraca dan arus kas harus dapat ditelusuri ke buku besar; saldo kas akhir sesuai neraca.
Pajak dan bagi hasil
Jenis/dasar/tarif serta masa berlaku ditetapkan finance saat kickoff. Keluaran pajak berupa kertas kerja
yang ditinjau, bukan pelaporan DJP otomatis. Dasar laba, rugi sebelumnya, cadangan dan porsi disetujui
owner. Pajak tidak dikurangkan dua kali bila dasar memakai laba setelah pajak.
Rekonsiliasi
HPP/nilai stok, penyusutan aset dan penyesuaian manual tetap diperiksa finance. Payroll diposting
setelah approval. Gateway membedakan nilai bruto, biaya, dana belum settlement dan kas diterima.
Posting menggunakan referensi unik.
Akses dan integrasi
Peran internal memakai izin sesuai fungsi; pelanggan/investor hanya mengakses miliknya, termasuk
lewat API/unduhan. Rahasia API disimpan di konfigurasi server. Callback sah dan idempotensi diuji. AI
tidak menyetujui diskon atau transaksi keuangan.
Penerimaan hasil
32 skenario UAT pada Excel: U01–U20 untuk versi awal, U21–U32 untuk tambahan dan siklus terpadu.
Pada tahap akhir, skenario awal diuji ulang. Semua skenario wajib lulus dan temuan kritis harus ditutup
sebelum rilis diterima.
Task diterima bila status Selesai, progres 100%, tanggal aktual mulai/selesai valid, hasil Diterima, nama
reviewer dan bukti terisi. Indikator task pada Excel membantu administrasi; keputusan rilis tetap
memerlukan hasil UAT, rekonsiliasi finance dan persetujuan owner.
