## Catatan

- **Gate 2 (keputusan rancangan):**
  - Tanpa skema baru: `sale.invoices.order_id` dan `customer_id` sudah nullable; hanya catatan kolom `customer_snapshot` di `docs.dbml` diperbarui.
  - Faktur tanpa SO wajib pelanggan aktif lewat kontrak `customer` (`getActiveCustomer`, `getSnapshot`); snapshot pelanggan disimpan untuk cetak.
  - PPN dihitung server dari tarif (11% bawaan) bila form mengirim `vatEnabled`; API lama yang tidak mengirimnya tetap memakai pajak per baris.
  - FU9: semua faktur (termasuk termin SO) hanya bisa diterbitkan dengan jatuh tempo.
  - Role Keuangan tidak punya `customer:read`, jadi pilihan pelanggan lewat `GET /sales/invoices/customer-options` (hak `invoice:create`).
  - `?ticketId=` mengisi pelanggan dan satu baris jasa dari tiket (dipakai B-31). Isi awal dari kontrak lisensi belum ada (belum ada layar penagihan lisensi).
- **Data seeder (A-10):** `invoice-demo.seeder.ts`, satu draf faktur tanpa SO `DEMO/INV/B42/0001` untuk pelanggan aktif pertama (dilewati bila belum ada pelanggan).
- **Tambahan di luar daftar file:** `customer/services/exported-customer.service.ts` (`activeCustomerOptions`), `sale/contracts/invoice.contract.ts` + `invoice.repository.interface.ts`, `sale/errors/invoice.errors.ts`, `sale/controllers/invoice.controller.ts`, `components/finance/invoice-list.tsx` (slot tombol), `routes/_authed/sales/invoices/$invoiceId/index.tsx` (badge/subjudul), `components/layout/build-crumbs.ts`, locale `api.ts` + `nav.ts`, `test/finance/ar-flows.test.ts`, `locale-parity.test.ts`.
- **Data uji di DB dev:** faktur `0002/INV/DEV/XI/26` (lunas), `0001/INV/DEV/XI/26` "Cek API" (dibuat saat mencari sebab F1, lalu dibatalkan), draf demo `DEMO/INV/B42/0001`.
- Sesi browser `finance_seed` sempat kedaluwarsa (POST 401); setelah login ulang alur berjalan. Bukan cacat kode.
